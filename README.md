# 資訊安全專案

## 專案概述
這是一個全端 web 應用，實作了完整的資訊安全設計方案。包含 7 項核心安全功能、6 項已實現的進階優化功能，以及 2 項規劃中的未來優化設計，展示從基礎安全到生產級監控的完整解決方案。後端使用 Node.js + Express，前端使用 React。

### 功能總覽
- **核心功能**: 用戶註冊與登入、JWT 認證、受保護資源存取
- **安全設計**: 5 項後端安全 + 3 項前端安全 = 8 項安全措施
- **已實現優化**: 結構化日誌系統、API 文檔、環境變數管理、CI/CD 集成、監控告警系統、自動化測試
- **未來規劃**: 容器化部署系統、多因素認證系統
- **特別功能**: CTF 挑戰和隱藏資源發現

### 架構
- `backend/`: Express 伺服器
  - `server.js`: 主應用程序和 API 路由
  - `logger.js`: 結構化日誌系統配置
  - `models/`: Sequelize 資料庫模型
  - `logs/`: 日誌文件目錄（應用日誌、安全事件日誌、錯誤日誌等）
  - `flag.txt`: CTF 挑戰的隱藏 flag
  - `server.test.js`: 後端單元測試和整合測試
- `frontend/`: React 應用
- `.github/workflows/`: CI/CD workflow 和自動化測試
- `scripts/`: 測試和部署腳本

### 部署方式
1. 安裝依賴：`npm install` (後端與前端)
2. 運行後端：`npm start` (在 backend/)
3. 運行前端：`npm start` (在 frontend/)
4. 存取 API 文檔：`http://localhost:3001/api-docs`

### 運行流程
1. 啟動後端伺服器 (http://localhost:3001)
2. 啟動前端應用 (http://localhost:3000)
3. 在前端註冊/登入，測試安全功能
4. 瀏覽 API 文檔 (`/api-docs`) 查看完整的 API 規範
5. 檢查日誌文件 (`backend/logs/`) 監控系統活動
6. 運行測試套件 (`npm test`) 驗證功能正確性
7. 檢查健康狀態端點 (`/health`) 監控系統狀態

## 安全設計說明

### 後端安全設計 (5 項)
1. **速率限制 (Rate Limiting)**: 使用 express-rate-limit 防止 DoS 攻擊。
2. **輸入驗證**: 使用 Joi 驗證用戶輸入，防止注入攻擊。
3. **密碼雜湊**: 使用 bcrypt 雜湊密碼，保護用戶憑證。
4. **JWT 認證**: 使用 JSON Web Token 進行身份驗證。
5. **授權控制**: 檢查令牌確保資源存取權限。

### 前端安全設計 (3 項)
1. **Content Security Policy (CSP)**: 在 index.html 中設定 CSP，防止 XSS。
2. **輸入消毒**: 在 React 中使用受控組件，防止惡意輸入。
3. **HTTPS 強制**: 使用 HTTPS 加密傳輸。

### 其他優化設計 (6 項)
1. **環境變數管理**: 使用 dotenv 管理敏感資訊，避免硬編碼。
2. **CI/CD 集成**: 使用 GitHub Actions 進行自動安全掃描。
3. **結構化日誌系統**: 使用 Winston 實現全面的日誌記錄，包括請求追蹤、安全事件記錄和錯誤監控。
4. **API 文檔**: 使用 Swagger/OpenAPI 提供完整的互動式 API 文檔界面。
5. **監控和告警系統**: 應用程式性能監控、錯誤追蹤和自動告警通知。
6. **自動化測試框架**: 完整的測試套件包含單元測試、整合測試和安全測試。

### CTF 挑戰 (額外加分)
專案包含一個隱藏的 CTF Flag 功能：
- **位置**: `backend/flag.txt`
- **存取方式**: `GET /secret-flag`
- **認證**: 需要 `x-ctf-token: infosec2026` header
- **用途**: 展示隱藏資源發現和安全測試概念

## 未來優化規劃

除了已實現的 6 項優化設計外，以下是兩個還可以進一步優化的設計規劃：

### 1. 容器化部署和編排系統
**目標**: 實現完整的容器化部署解決方案，提升應用的可移植性和擴展性。

#### 規劃內容
- **Docker 容器化**: 將應用程式和依賴打包成 Docker 容器
- **多階段建置**: 優化 Docker 映像大小和建置效率
- **容器編排**: 使用 Docker Compose 或 Kubernetes 進行多容器協調
- **環境隔離**: 開發、測試、生產環境的容器化配置

#### 預期效益
- **可移植性**: 應用程式可在任何支援 Docker 的環境中運行
- **擴展性**: 輕鬆進行水平擴展和負載均衡
- **一致性**: 消除"在我機器上可以運行"的問題
- **DevOps 友好**: 簡化部署流程和環境管理

#### 技術選項
- Docker, Docker Compose
- Kubernetes (k8s)
- Helm Charts
- CI/CD 整合的容器建置流程

### 2. 多因素認證系統 (2FA/MFA)
**目標**: 在現有 JWT 認證基礎上增加多因素認證，提升帳戶安全性。

#### 規劃內容
- **TOTP 認證**: 基於時間的一次性密碼 (Time-based One-Time Password)
- **SMS 驗證**: 通過簡訊發送驗證碼
- **Email 驗證**: 通過郵件發送驗證碼
- **硬體金鑰支援**: FIDO2/WebAuthn 標準支援

#### 安全增強
- **防範密碼洩露**: 即使密碼被盜，仍需第二因素驗證
- **防範中間人攻擊**: 多層驗證機制
- **合規要求**: 滿足金融和企業的安全標準
- **用戶體驗**: 平衡安全性和便利性

#### 實現架構
- **認證流程**: 密碼驗證 → 第二因素挑戰 → 令牌生成
- **備用機制**: 提供備用驗證方式，避免用戶被鎖定
- **管理介面**: 用戶可管理自己的第二因素設備
- **審計日誌**: 記錄所有 MFA 相關的安全事件

#### 技術選項
- speakeasy (TOTP)
- twilio/nexmo (SMS)
- nodemailer (Email)
- WebAuthn API (硬體金鑰)

## 進階功能說明

### 結構化日誌系統 (優化設計 3)
實現了完整的日誌記錄和監控系統：

#### 日誌功能
- **請求追蹤**: 記錄所有 HTTP 請求的開始和完成時間、IP 地址、User-Agent
- **安全事件記錄**: 專門記錄登入嘗試、認證失敗、速率限制觸發等安全事件
- **錯誤監控**: 捕獲並記錄應用程序異常和未處理的 Promise 拒絕

#### 日誌文件
- `logs/app-*.log`: 一般應用日誌
- `logs/error-*.log`: 錯誤日誌
- `logs/security-*.log`: 安全事件日誌
- `logs/exceptions-*.log`: 未捕獲異常日誌
- `logs/rejections-*.log`: Promise 拒絕日誌

#### 日誌格式
使用結構化 JSON 格式，包含時間戳、事件類型和詳細的上下文信息，便於日誌分析和監控。

### API 文檔系統 (優化設計 4)
提供完整的 API 文檔和測試界面：

#### 功能特性
- **OpenAPI 3.0 規範**: 符合業界標準的 API 文檔格式
- **互動式界面**: Swagger UI 提供可直接測試 API 的網頁界面
- **完整端點文檔**: 涵蓋所有 API 端點的請求/響應格式、參數說明和認證要求

#### 存取方式
- **文檔界面**: `http://localhost:3001/api-docs`
- **JSON 規範**: `http://localhost:3001/swagger.json`

#### 文檔內容
包含以下 API 端點的詳細說明：
- `POST /register`: 用戶註冊
- `POST /login`: 用戶登入
- `GET /protected`: 受保護資源（需要 JWT 認證）
- `GET /secret-flag`: CTF 隱藏端點（需要特殊 header）

### 安全監控與合規
結合日誌系統和 API 文檔，專案實現了：
- **安全事件追蹤**: 所有安全相關事件都會被記錄
- **審計追蹤**: 完整的請求日誌用於安全分析
- **開發者友好**: 清晰的 API 文檔便於安全測試和集成

### 監控和告警系統 (優化設計 5)
實現生產級的應用程式監控和告警機制：

#### 監控功能
- **應用程式性能監控**: 響應時間、吞吐量、錯誤率追蹤
- **系統資源監控**: CPU、記憶體、磁碟使用率監控
- **錯誤追蹤**: 自動捕獲和分類應用程式錯誤
- **健康檢查端點**: `/health` 端點提供系統狀態檢查

#### 告警機制
- **即時告警**: 當系統出現異常時發送通知
- **閾值告警**: 設定性能指標閾值，超過時觸發告警
- **安全告警**: 檢測到安全事件時立即通知
- **多渠道通知**: 支持郵件、Slack、Webhook等多種告警方式

#### 監控儀表板
- **即時儀表板**: 提供系統狀態的即時視圖
- **歷史趨勢**: 性能指標的歷史數據分析
- **告警歷史**: 記錄所有告警事件和處理狀態

### 自動化測試框架 (優化設計 6)
建立完整的測試生態系統，確保程式碼品質和安全性：

#### 測試類型
- **單元測試**: 使用 Jest 測試個別函數和模組
- **整合測試**: 測試 API 端點和資料庫操作
- **端到端測試**: 模擬用戶完整操作流程
- **安全測試**: 自動化安全漏洞掃描

#### 測試工具
- **Jest**: JavaScript 測試框架
- **Supertest**: API 端點測試
- **OWASP ZAP**: 自動化安全掃描
- **Postman/Newman**: API 測試自動化

#### CI/CD 整合
- **測試自動化**: 每次代碼提交自動運行測試
- **覆蓋率報告**: 生成測試覆蓋率報告
- **品質門檻**: 設定測試通過率和覆蓋率的最低要求
- **安全掃描**: 自動化安全漏洞檢測

#### 測試覆蓋範圍
- **API 端點**: 所有 REST API 的功能測試
- **認證邏輯**: JWT 認證和授權測試
- **輸入驗證**: 惡意輸入和邊界條件測試
- **安全功能**: 速率限制、加密、CSP 等安全措施測試

## 資料庫建置方式與資料表設計

### 資料庫
使用 SQLite 作為資料庫，檔案儲存在 `backend/database.sqlite`。

### 建置方式
1. 安裝依賴：`npm install sqlite3 sequelize`
2. 啟動後端：`npm start`，Sequelize 會自動同步資料庫。

### 資料表設計
#### User 表
- **id**: INTEGER (主鍵，自動增量)
- **username**: VARCHAR(255) (唯一，非空)
- **password**: VARCHAR(255) (非空，雜湊儲存)
- **createdAt**: DATETIME (自動)
- **updatedAt**: DATETIME (自動)

**注意**: 密碼欄位儲存 bcrypt 雜湊值，不儲存明文密碼。
